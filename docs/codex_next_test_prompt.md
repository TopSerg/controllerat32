# Codex prompt — QS138 next test

Подтяни ветку `test/overcurrent-flight-recorder` репозитория `TopSerg/controllerat32`, прочитай `docs/qs138_next_test_overcurrent_2026-10-06.md`, собери прошивку и проверь, что все изменения для flight recorder и safe-start interlock присутствуют.

Дальше веди оператора по испытанию строго по методологии: перед каждым физическим действием на силовом стенде явно указывай следующий шаг и ожидаемые значения, а после выполнения шага анализируй фактические CAN/JTAG данные перед переходом дальше.

Не менять `QS138_OVERCURRENT_TRIP_A = 20 A`, не включать `DecouplingEnable`, не менять provisional параметры QS138 и не мержить ничего в `main`. CONTROL/PWM допускается только на неподвижном валу с `Id=0`, `Iq=0`; внешний разгон выполняется по ступеням из методологии без выключения PWM между точками. При любом fault остановить дальнейшие шаги, сохранить CAN/JTAG лог, до очистки ошибки выгрузить `g_qs138FlightRecorder` и декодировать его через `tools/decode_qs138_flight_recorder.py`. Логи сохранять в `test_logs/` с датой и временем.

На каждом этапе кратко фиксируй: скорость, Ia/Ib/Ic, Id/Iq и refs, Ud/Uq, UmodRef, Udc, FluxPositionError, fault-флаги и решение — продолжать или остановить тест.
